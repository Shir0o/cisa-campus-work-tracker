Ink · shell comparison

Top bar vs rail

Same page, same content, same tokens — only the shell differs. Both are in Ink, so this is a navigation question, not a colour one.

Top bar Rail
Content width at 1440 1280px 1148px — 10% narrower
Destinations in view 5, then a More menu All 13, in four groups
Reaching a buried one Two clicks, one of them a menu you have to remember exists One click
Space above the fold 98px to first content 82px — a wash
Wide monitors Bar spans the full width; content caps at 1280 and floats in the middle Rail is fixed, so every extra pixel goes to content
Mobile Hamburger → drawer Unchanged — rail is lg: and up, MobileNav still owns small screens
Cost to build Nothing. It is the shell you already have, retoned by the token swap. TopNav.tsx rewritten, PageContainer gutters moved, a new home for the impersonation banners
Reads like the reference No Yes — this is the thing that makes it look like the image

The 132px the rail takes is the real cost, and it is worth it: it buys back the More menu, which currently hides ten of a full-timer's thirteen destinations. If content width mattered more than navigation here — a dense table view, say — the top bar would win instead.
