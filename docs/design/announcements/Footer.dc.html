The bar at the bottom

When you can’t post, the composer is replaced by one line of italic grey text and four emoji. It is the whole of the member’s side of the feature, and each of its three parts is wrong in a different way — one of them says out loud that something exists which doesn’t.

It describes a route that isn’t built. “Replies go to the team directly” reads as an instruction — reply, and it reaches the team. There is nowhere to reply. The same gate that hides the composer is passed to MsgThreadPane as canPost, so the thread reply box is closed too. A member’s only way to answer is to leave, remember who posted, and start a direct message.

2

The emoji attach to the wrong message. They react to messages[messages.length - 1] — whatever is newest — regardless of what you have scrolled to. Reading Monday’s post and tapping 🙏 puts your reaction on today’s, silently, with no feedback that anything happened anywhere.

3

Italic grey is the app’s voice for absence. Every other italic --text-mute rule on this page is a nothing-here: .msgb-gone (a deleted message), .msgs-item-gone (a deleted conversation), .msgs-people-empty (an empty list). The member’s whole side of the feature is set in the typography the app reserves for what isn’t there.

The open question

Where a reply should go

The current copy asserts an answer the code doesn’t implement, so this has to be settled rather than inherited. Three routes, each with a real case for it.

To the poster Drawn

“Reply to Naomi” opens — or reuses — a direct chat with whoever wrote the post, with the announcement quoted into it so she knows what it’s about.

Why: it is the only reading of the existing copy that is true, it needs no new room type, and getOrCreateDirectChat already does exactly this. Costs: if three Full-timers post to one channel, a member’s replies scatter across three chats.

To a staff group

Replies land in one group chat that all the channel’s Full-timers are in, so whoever is around picks it up.

Why: it is closest to “replies go to the team” as written, and no reply falls on one person’s day off. Costs: a member’s question about the rota is now visible to every Full-timer, which is a different privacy promise than a direct message.

Threads, opened up

Keep replies in the channel, but only inside a post’s thread — the pane already exists and is already closed off by the same canPost flag.

Why: the conversation stays attached to what it is about, and the UI is built. Costs: it makes an announcement a discussion, which is the thing the room type exists to prevent — and it needs a firestore.rules change to let non-admins write messages with a parentId but not without one.

Drawn as option one because it is the smallest change that stops the app promising something it doesn’t do. If option two is the intent, the copy is right and only the wiring is missing; option three is a bigger feature than this issue, and worth its own.
