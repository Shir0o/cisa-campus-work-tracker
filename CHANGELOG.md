# Changelog

A distilled history of notable changes to CISA Campus Work Tracker, newest first.
This project is not version-tagged; entries are grouped by month. Format loosely
follows [Keep a Changelog](https://keepachangelog.com/) (Added / Changed / Fixed).

## [Unreleased]
### Removed
- **Drop "How we met" and "Address" from new-contact and contact-edit forms (#730)** — The fixed-vocabulary "How we met" select and freeform ADDRESS input are gone from the new-contact modal (`NewContactModal.tsx`), the contact-detail edit modal (`ContactDetailsModal.tsx`), and the public sign-up form. The audit log no longer diffs these fields (`diffContactFields` in `packages/core/src/contactDetail.ts`) and the contact-detail read-only view no longer renders them. The `location` field is no longer written by any path (`NewContactModal`, `ContactDetailsModal`, `SignUp`, mobile `LogSheet`/`addContact`/`updateContact`, and the Gemini quick-add server), and the mobile `ContactScreen` `DetailRow` for both fields is removed. Existing data on disk is preserved (the schema is unchanged); only the UI/forms stop writing or surfacing them. **Follow-up TODO** in `src/views/Visits.tsx` and `src/views/VisitsMobile.tsx` (the overdue strip's `contact.location` fallback became `t('visits.no_location_noted')` since `Contact.location` no longer surfaces — a real `visitAddress` field on the Visit doc, or making `where` required at log time, is the proper follow-up).

### Fixed
- **Center navigation destination icons in collapsed rail mode (#728)** — In collapsed/compact navigation rail mode (`rail-collapsed`), destination links (`RailItem`), external links (`RailExternalItem`), and the public sign-up form link now use `mx-auto` instead of `mx-2`, centering their 44×44 square tiles and glyphs along the exact vertical centerline of the rail (matching the header sheep logo tile, settings icon, and collapse button).

### Changed
- **Stage select on new-contact form lists every configured stage (#730)** — The "Where they're at" select no longer falls back to a hardcoded "First Contact" — when the `stages` collection is empty it now defaults to "Unassigned" only, and when stages are configured it lists every stage in `order` ascending order plus "Unassigned". Replaced the now-unused `HeartHandshake` and `MapPin` icon imports; the `modals.how_we_met*`, `modals.address*`, `modals.contactDetails.how_we_met*`, `modals.contactDetails.address*`, and mobile `mobile.contact.how_we_met` / `mobile.contact.address` i18n keys were removed in `en.json` and `es.json`.
- **Replace "holding" with "praying for" on the prayer surface (#704)** — The `/prayer` page and every other user-facing string that used "holding"/"hold" as the prayer-action verb now reads "praying for"/"pray for" (English) and "orar por"/"oramos" (Spanish). Affected keys: `prayers.who_are_we_holding`, `already_held`, `try_all_to_see`, `write_what_holding`, `start_holding`, `people_we_are_holding`, `no_one_to_hold`, `try_another_name`, `find_person_above`, `hold_someone_in_prayer`, `no_one_here_yet`, `no_brothers_to_hold_yet`, `no_sisters_to_hold_yet`, `search_anyone_to_hold`, `write_what_holding_mobile`, plus the landing/My Day/Coordination strings `caring_for`, `prayers_to_hold`, `tasks_to_hold`, `and_prayers_to_hold`, `what_were_holding`, `coordination.todo_sub`, and `contactDetails.prayers_we_re_holding`. The hardcoded `Prayers you're holding` section heading and intro copy on `LandingTrainee` were also rewritten to match. Dictionary key names are unchanged so existing call sites keep working.
- **GroupMe sender teammate matching & contact creator attribution** — When incoming GroupMe triggers arrive via `/api/webhook/groupme`, the backend now checks whether the GroupMe sender name matches a registered teammate in the `users` collection. If matched, the created contact and logged interaction are attributed directly to that teammate's account UID and full name with `owner` automatically assigned, preventing GroupMe entries from appearing as unassigned or generic "Someone" in contact care lines and activity feeds. Added instructions in Settings for iOS Shortcuts, Home Screen widgets, and Siri voice automations. Covered by unit tests in `src/test/server.test.ts`.
- **Fix mobile FAB touch responsiveness, keyboard avoidance in bottom sheets, and multiline caret jumping (#724)** — Configured `BottomSheetModal` with `keyboardBehavior="interactive"`, `keyboardBlurBehavior="restore"`, and `android_keyboardInputMode="adjustResize"` to dynamically resize and prevent keyboard overlap across mobile bottom sheets (such as "Someone new"); added `hitSlop` to the QueueScreen floating action button (`+`); and disabled `autoCorrect` on `V2TextArea` to prevent asynchronous text clobbering and caret jumping when typing or backspacing in multiline notes. Added regression unit test coverage in `Sheet.test.tsx`.
- **Impersonation view greeting and user-scoped data filtering (#679)** — Provided `effectiveUserName` from `AuthProvider` representing the active impersonation target persona / preview role label, and ensured `MyDay.tsx`, `MyDayMobile.tsx`, `LandingTrainee.tsx`, `LandingStudent.tsx`, `LandingCommunity.tsx`, `TopNav.tsx`, and `NavRail.tsx` use `effectiveUserName` and `effectiveUserId` for greetings, user data subscriptions, and waiting count queries during impersonation or role simulation.
- **Guaranteed Auth loading state clearance on initialization/provisioning error** — Wrapped `onAuthStateChanged` in `src/components/AuthProvider.tsx` in a `try...catch...finally` block so `loading` is always cleared even when Firestore document retrieval or provisioning encounters network, permission, or storage partitioning errors. This prevents `ProtectedRoute` from permanently hanging on the full-page Skeleton Loader when invited users sign in or experience transient errors. Added matching unit tests in `src/test/AuthProvider.test.tsx`.
- **Remove season and semester chip from top header strip in rail mode (#675)** — Removed standalone `<SeasonChip />` from the desktop `NavChromeStrip` header bar so semester/year information is housed cleanly in the profile dropdown menu across all navigation layouts. Added unit tests in `src/test/NavChromeStrip.test.tsx`.
- **Fix Role select dropdown arrow alignment in "Add someone by email" modal (#717)** — Wrapped the Role dropdown in `PreAddModal` (`Settings.tsx`) in a relative container with `appearance-none`, explicit right padding (`pr-10`), and an absolutely positioned `<ChevronDown />` icon to ensure consistent cross-browser arrow positioning and prevent native arrow clipping. Added unit test coverage in `Settings.test.tsx`.
- **Add Sign-up form link to desktop navigation rail (#676)** — Added the Sign-up form destination link (`/signup`) to `NavRail.tsx`, making it accessible on the desktop navigation rail in both expanded and collapsed (compact) modes with tooltip and accessible label support, matching the top-bar More menu and mobile navigation drawer.
- **Contact Details Tab Bar Height Invariance (#684)** — Enforced uniform `48px` min-height and centered vertical alignment across `.cd-tabs-bar` and `.cd-tab` buttons in `src/index.css`. This prevents the tab navigation bar from narrowing or jittering in height when selecting the badge-less "Overview" tab versus tabs with count badges ("Follow-up", "Interactions", etc.). - **Deep-link and route notification bell items to target pages (#682)** — Clicking items in the notification bell now routes directly to the correct destinations: registered the `/messages/:roomId` route in `App.tsx` and synchronized `useParams().roomId` with active room selection in `Messages.tsx`; ensured notification emitters across `asks.ts` (`/questions`), `threads.ts` (`/people/:id?tab=thread`), `LogInteractionModal.tsx` (`/people/:id`), `NewContactModal.tsx` (`/people/:id`), and `todos.ts` (`/coordination` or `/`) provide explicit `link` properties; and hardened `NotificationCenter.tsx` selection fallback navigation.
- **fix(ci): migrate seed-emulator.ts to firebase-admin v14 modular API** — The E2E CI workflow (`e2e.yml`) had been failing for 5+ consecutive daily runs because `scripts/seed-emulator.ts` still used the legacy `import admin from 'firebase-admin'` namespace (removed in v14). The `admin.apps` property was `undefined`, causing a `TypeError` at startup before Playwright ever launched. Migrated all 7 call sites to the modular API (`initializeApp`/`getApps`/`getApp`/`getAuth`/`FieldValue`), matching the pattern already used in `server.ts` since commit `3185380`.
- **Word-boundary name matching in Quick Add & GroupMe/SMS webhooks (#731)** — `findExistingContact` in `server.ts` was collapsing a typed "Robert" into an existing "Roberto Garcia" contact via bidirectional substring containment, so a GroupMe `!add Robert` (or SMS / Quick Add) silently merged the new person onto the wrong record. The fuzzy fallback now only matches when the substring sits on a word boundary in both directions, preserving the documented "Jonathan" → "Jonathan Doe" behavior while preventing prefix-only false positives. Added two regression tests in `src/test/server.test.ts` covering `Bob` ↔ `Bobby` and `Robert` ↔ `Roberto Garcia`.

### Changed
- **Global Search (⌘K) is a centred popup, not an anchored dropdown (#689, spec #695)** — The desktop palette no longer hangs off the 300px topbar field. The field becomes a button (same Bento SearchBar look from #653, but with a permanent ⌘K pill and no query of its own) and the caret moves into the popup's own 56px field row, so the input and the results it drives sit together. The panel is portalled to the body and centred 96px from the top on a `bg-black/40 backdrop-blur-sm` scrim — which also fixes the palette landing in two different places depending on whether the rail or the top bar mounted it. Freed from the field it was tethered to, the panel goes 420px → 640px (capped at `calc(100vw-2rem)`) on the `--shadow-pop` elevation, and the results region 440px → `min(62vh,520px)`, so conversation snippets and note titles read as sentences instead of ellipsising mid-phrase. The panel is a real `role="dialog" aria-modal` with an accessible name; focus enters the field on open and returns to the trigger on close; the scrim replaces the old container-bounded click-away; and the footer hint gains “ · esc close” (both locales) alongside a new `esc` chip in the field row, because a modal has to teach its own exit. Everything inside the panel — rows, tonal nodes, group labels, role gating, frecency ranking, quick actions, shortcut listing, the history opt-in — is unchanged, as is the mobile overlay, which was already full-screen. Covered by 7 new tests and 4 rewritten structural ones in `src/test/GlobalSearch.test.tsx` (42 total), all through the existing `render(<GlobalSearch />)` seam.
- **Ink — the application wears a near-monochrome shell (#663)** — Bento's cool-blue neutrals and violet `#5C17E5` accent are gone. The `@theme` block and the two theme blocks in `src/index.css` are the whole change: `--bg`/`--panel` exchange roles (white page, grey cards), `--accent` and friends become near-blacks (light) and inverted near-whites (dark), `--accent-on` becomes theme-dependent for the first time (white content in light, near-black in dark) so the primary button reads correctly in both themes, signal colours (success/warning/danger and their containers) carry over unchanged, the eight data-hue angles and the legacy `board-*` names are preserved while chroma and lightness go up so the stage/board hues carry more weight as the only chroma on screen, and the shape scale gains `--radius-xl` (32px) and `--radius-pill` (999px). The `--font-serif` alias now points at Plus Jakarta Sans (loaded at 600/700/800 alongside Lexend) and the base `h1/h2/h3/.serif` rule bumps to 700, so headings visibly lead the body. The only non-stylesheet change is the notification badge in `NotificationCenter.tsx`, which had hardcoded `text-white` on `bg-primary` and now uses `text-on-primary` so it inverts correctly in dark mode. No component markup was retouched — roughly 4,254 existing semantic utility usages re-theme through the token swap. The new shape, the dark-mode walk, and the existing colour-token regression guard together replace the previous selection-state audit, which had been pre-factored onto solid fills in #660. The change reverts in a single commit if the team wants to step back.

- **"Questions for the team" moved out of Messages onto its own page (#646, #647)** — The question channel was a row in the Messages rail rendered with the chat grammar: a stream of bubbles and a composer pinned to the bottom. Everywhere else in Messages that composer means "reply to what's open"; there it called `addAsk` and posted a *new question*, while answering was a 12.5px "Answer this" link opening a third pane. The route is staff-only (`admin` + `manager`) and lands in the **More** menu — where Messages already lives for a Full-timer, whose primary tabs are Coordination Notes / People / On our hearts — labelled "Questions" because the full name does not fit the 224px menu. Since folding a destination away costs discoverability, `TopNav` leaks it: the same 7px accent dot the Messages rail uses for unread now sits on **More**, and the count of questions still waiting rides the menu row in the amber `askWaitedWords` already uses. Adds a `/questions` entry to `NAV_ICONS` (`MessageCircleQuestion`) rather than falling through to `LayoutDashboard` (#647). Covered by `src/test/Questions.test.tsx` (answering goes through `addAskReply` and never `addAsk`; no textbox exists until the ask panel is opened; the recorder cannot send without picking a person; role-simulation writes stay bound to the real uid per #603) and updated `permissions.test.tsx` / `Messages.test.tsx`. My Day's `AskStack` is deliberately untouched — whether it keeps answering inline is tracked in #646.
