# Changelog

A distilled history of notable changes to CISA Campus Work Tracker, newest first.
This project is not version-tagged; entries are grouped by month. Format loosely
follows [Keep a Changelog](https://keepachangelog.com/) (Added / Changed / Fixed).

## [Unreleased]
### Added
- **Unified Attention Feed with Done / Followed-up action (#330)** — Unified "What needs my attention" into a single cohesive feed component (`src/components/landing/AttentionFeed.tsx`, `src/lib/attention.ts`) across desktop and mobile My Day (`src/views/MyDay.tsx`, `src/views/MyDayMobile.tsx`). Signals across contacts, subcollection interactions, message threads, assigned tasks, and notifications are collapsed into stacked rows per contact/target, grouped into calendar date buckets (`today`, `yesterday`, `thisWeek`, `lastWeek`, etc.) using `dateBuckets.ts`. Each stack provides an explicit "I followed up" / "Done" action backed by `UserEntityState` (#326) to resolve the whole stack or individual items, inline expandable item details, unread count badges, "Mark all scanned", and a "Comment" shortcut directly opening the contact's thread tab. Added unit and component tests in `src/test/attention.test.ts` and `src/test/AttentionFeed.test.tsx`.
- **Audit and derive Contact activity fields (#329)** — Created shared activity derivation utilities (`src/lib/contactActivity.ts` and `@cisa/core` `packages/core/src/data/contactActivity.ts`) to uniformly update contact activity metadata (`lastSeen`, `lastContactedDate`, `lastContactedBy`, `lastContactedById`, `hasNewActivity`, and audit stamps). Wired unified activity patch updates into interaction logging (`ContactDetailsModal.tsx`, `LogInteractionModal.tsx`, and `@cisa/core` `addInteraction`), visit mirror syncing (`src/lib/visits.ts`), and attendance marking (`src/views/Attendance.tsx` and `@cisa/core` `setContactAttendance`). Added unit tests in `src/test/contactActivity.test.ts` and `packages/core/test/contactActivity.test.ts`.
- **Notification stacking by target (#331)** — Collapsed multiple notifications referencing the same `targetId` into a single stack row with count pill badge (e.g. `2 updates`) in `NotificationCenter.tsx`. Clicking the stack header or expand action unveils the individual child notifications with separate click navigation and dismiss controls. Added whole-stack "Set aside" batch action to dismiss/delete all notifications within a stack. Added `groupNotificationsIntoStacks` helper and comprehensive unit tests in `src/test/NotificationCenter.test.tsx`.
- **Unified read/done state store (#326)** — Added `src/lib/userEntityState.ts` providing a cohesive per-user entity state store with two orthogonal axes: `read` (passive awareness / scanned) and `done` (active resolution / hidden / cleared), backed by localStorage (`cisa.user.entity.<uid>`) with automatic pub/sub reactivity. Transparently migrates and backs legacy stores (`InboxReads` in `src/lib/inboxReads.ts`, `ConvHides` in `src/lib/convHides.ts`, and `MessageHides` in `src/lib/messageHides.ts`), maintaining full backward compatibility. Added `useUserEntityState` and `useEntityState` React hooks, and unit tests in `src/test/userEntityState.test.ts`, `src/test/inboxReads.test.ts`, `src/test/convHides.test.ts`, and `src/test/messageHides.test.ts`.
- **Live contact pill with hover preview (#334)** — Implemented live contact entity pills (`src/components/ui/ContactPill.tsx`) replacing static/stale display caches for contact attachments in message threads (`src/views/Messages.tsx`) and mobile chat (`apps/mobile/src/components/messages/ChatThreadScreen.tsx`). Contact pills subscribe to live Firestore contact data and stages, displaying current stage color (`StageChip`), initials avatar, and name. On desktop hover/focus, a viewport-aware floating preview card displays contact details (year, major, live stage, last contacted status, caregiver) and an "Open [Name]'s page" button opening the full detail modal. On mobile/touch, tapping toggles the preview with tap-to-profile navigation. Unit tests in `src/test/ContactPill.test.tsx` and `src/test/Messages.test.tsx`.

- **Frecency ranking in Global Search (#328)** — Implemented Macro-style frecency scoring (`src/lib/frecency.ts`) for Global Search (`GlobalSearch.tsx`) backed by a per-user, namespaced localStorage store (`cisa.frecency.<uid>`) with pub/sub reactivity. Scoring follows $\text{score} = 0.7 \times \log_2(\text{event\_count} + 2) + 0.3 \times \sum_{i=1}^{\min(N,10)} \exp(-0.1 \times \text{hours\_ago}_i) \times \text{weight}_i$ (weights: open = +2.0, ping = 0.0, close = -1.0). Contacts frequently opened by the user now float to the top of the no-query "Recent people" list; search query matches and destinations are ranked by frecency score descending. Added quick-close demotion tracking (< 6 seconds without user interaction) in `ContactDetailsModal.tsx`. Added unit tests in `src/test/frecency.test.ts`, `src/test/GlobalSearch.test.tsx`, and `src/test/ContactDetailsModal.test.tsx`.

### Fixed
- **On `/coordination`, editing a page threw your caret to the bottom, wiped what you
  had selected, and made Cmd/Ctrl+Z jump to the end of the document.** All three came
  from one line in the bi-directional task sync added by #174: the effect serialized the
  *whole* page to Markdown, diffed it line-by-line against Firestore, and on any
  difference called `editor.commands.setContent(...)` — a whole-document delete+insert.
  With `Collaboration` active that rewrites the entire `Y.Doc`, so ProseMirror mapped
  the selection to the end of the new document, the Markdown round trip lost anything
  Markdown can't express, and (since `StarterKit` runs with `undoRedo: false` and Yjs
  owns history) each rewrite landed in the undo stack as one giant entry. It fired
  constantly, because `todos`/`team` are fresh arrays on every Firestore snapshot —
  including the snapshots the editor's own 1.2s save triggers — and because comparing
  serialized Markdown lines against `formatDocTaskMarkdown` output reads as "changed"
  forever for any indented task or any title containing Markdown punctuation. The sync
  now works on `taskItem` *nodes*: `planDocTaskEdits` (`src/lib/board.ts`) works out
  which checklist lines actually went stale, and the editor patches just those in one
  transaction marked `addToHistory: false`, so a teammate's change is never something
  you can undo. The line your caret is in is skipped and re-syncs once you move off it.
  `syncMarkdownWithTasks` is gone, replaced by `formatDocTaskText`/`parseDocTaskText`
  so both directions share one format. Markdown source view took the same treatment:
  its five whole-document rewrites now go through one helper that no-ops when the text
  is unchanged and restores the caret otherwise.
- **The Board showed the same person three or four times in its live-presence stack,
  and repeated their name label inside the editor.** Confirmed against production
  RTDB: `board_docs_rtdb/{docId}/awareness` held five frozen client nodes against one
  live editor on the F26 TC page, four of them the same person. Two things were wrong.
  (1) `src/lib/yjsRtdbProvider.ts` leaked presence nodes — `destroy()` cancelled the
  `onDisconnect` remove *before* firing its own best-effort delete, so any unmount
  whose delete didn't land (tab closed on a page switch, offline, suspended mobile
  WebView) orphaned the node permanently; and a client whose initial read failed
  returned from `bootstrap()` without ever arming `onDisconnect` yet kept publishing
  presence anyway. Publishing is now gated on `onDisconnect` actually being armed,
  `destroy()` leaves the server-side remove in place as the backstop, and `pagehide`
  is handled alongside `beforeunload` (the latter never fires on iOS). A new reaper
  deletes the RTDB node whenever `y-protocols` times a peer out at 30s, so any client
